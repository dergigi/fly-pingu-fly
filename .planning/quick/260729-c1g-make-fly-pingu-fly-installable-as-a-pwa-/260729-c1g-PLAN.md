  <action>
  Expand the tracer PWA config so Vercel redeploys stay healthy for a Phaser static game:

  1. In `VitePWA` `workbox` options set `cleanupOutdatedCaches: true` and `navigateFallback: 'index.html'`.

  2. Keep precache lean: configure `globPatterns` so the SW precaches the app shell (html/js/css/webmanifest/icons) and does not attempt to forever-precache the entire unused `public/assets/sprites` dump. Prefer runtime caching for `/assets/` game media.

  3. Add `runtimeCaching` entries using Workbox `NetworkFirst` for:
     - document/navigation requests (short `networkTimeoutSeconds`, e.g. 3)
     - same-origin `/assets/` paths (sprites/media the game loads)
     Give each a named `cacheName`, `expiration.maxEntries`, and bounded `maxAgeSeconds` (days-scale, not indefinite) so a bad deploy cannot pin stale game media forever. Rely on `registerType: 'autoUpdate'` already set in Task 1 for worker replacement.

  4. If Workbox warns about large files, raise `maximumFileSizeToCacheInBytes` only as needed for hashed bundle chunks — not as an excuse to precache every decorative sprite.

  5. Re-run production build and confirm `dist/sw.js` exists and references NetworkFirst / cleanup behavior. No new dependencies. No vercel.json unless build proves a content-type issue (default Vite→Vercel static is enough).
